(C) 是在固定同一份日前购电量 ĝ 后，让储能做全年完美预见 LP 得到的费用。 由于购电费 Σ p·ĝ·Δt 完全相同，而紧急购电逐槽满足 e ≥ L−P−ĝ−d，所以 (C) 是任何策略都达不到的下界。 该计划的诚实执行成本是 18,779,159 元，其中 914,735 kWh 放电量被 SOC 下限卡掉。

§0结论速览

  • 1 现交付计划在算术上不可能实现。报 13,832,465 元，其同 ĝ 物理下界是 15,347,211 元，低出 1,514,746 元。
  • 2 其诚实执行成本为 18,779,159 元，比自报高 35.7%，且高于点预测方案的诚实执行成本 17,062,165 元。 因此"随机规划相对点预测节省 8.36%"不成立。
  • 3 把储能层拉平后，SP 的日前购电量 ĝ 反而被点预测方案占优：同 ĝ 完美预见下 15,347,211 元 vs 14,668,624 元，差 678,587 元。SP 的"省钱"全部来自那份放不出来的 d̂。
  • 4 根因：SOC 递推用情景平均充电 E[c̄]， 而 d̂ 是一阶段承诺量。实际充电在缺电情景被削到 0，实际 SOC 恒低于计划 SOC。
  • 5 替代算法：日前只承诺 ĝ，储能与紧急购电降为二阶段追索，槽级能量平衡作唯一耦合约束。 可立即采用的安全版本（γ=1 可交付计划）年内可保证 15,187,755 元，对全年实测约 15.39–16.02 M 元。

对"随机规划优于点预测"的证伪

把两份计划的日前购电量 ĝ 摘出来，用同一把尺子（(C) 同 ĝ 完美预见）量： 点预测方案的 ĝ 值 14,668,624 元，现交付两阶段 SP 的 ĝ 值 15,347,211 元 —— 储能层拉平之后，SP 的购电计划被点预测方案占优 678,587 元。

所谓"相对点预测节省 8.36%"（13,832,465 vs 15,094,675），是把 (B) 口径的数与 (A) 口径的数相减， 而其中 (A) 那个数根本不可实现。

根因

# 代码/problem2_stochastic.py 的 SOC 递推（原文注释）
# 等式：SOC 递推（T 行）。充电按【场景平均】E[c̄] 计入：
#   S_{t+1} − S_t − ETA·Δt·(1/K_d)·Σ_ω c̄_{t,ω} + (Δt/ETA)·d̂_t = 0

d̂_t   ← 一阶段变量：0:00 就承诺下去的放电功率
E[c̄]  ← 情景平均：一个不存在的"平均场景"的充电量
真实充电  c ≤ max(0, P + ĝ + d − L)   ← 缺电情景里恒为 0

d̂_t 与 E[c̄] 被放进了同一个等式，于是实际 SOC 轨迹严格低于计划 SOC 轨迹，缺口随缺电情景累积， d̂ 承诺的电就放不出来。 这不是数值误差，是模型层的口径不一致：计划层（一阶段承诺）与执行层（情景内实现） 用了两套储能物理。commit abd42f6 的提交信息本身已把这一点记为未解决问题。

§3替代算法一 · 储能降为追索变量

日前 0:00 真正需要承诺的只有购电量 ĝt。 储能充放电 c、d 与紧急购电 e 本来就由当天实际负荷/光伏决定， 把它们写成一阶段承诺量，正是 §2 病根所在。 

min_{ĝ ≥ 0}   Σ_t p_t ĝ_t Δt  +  (1/K) Σ_ω [ Σ_t 5 p_t e_{t,ω} Δt ]

s.t.  逐情景 ω：
      SOC 递推     S_{t+1,ω} = S_{t,ω} + η Δt c_{t,ω} − (Δt/η) d_{t,ω},  S_{0,ω} = S
      SOC 区间     1200 ≤ S_{t,ω} ≤ 10800
      功率         0 ≤ c_{t,ω}, d_{t,ω} ≤ 5000
      能量平衡     c_{t,ω} − ĝ_t − d_{t,ω} − e_{t,ω} ≤ P_{t,ω} − L_{t,ω}   ← 唯一耦合约束
      非负         e_{t,ω} ≥ 0

能量平衡是唯一必需的耦合约束：取 c = 0 即得 e ≥ L − P − ĝ − d（"紧急购电只补负载缺口"，无需另写）； 同时保证任何充进电池的电都必须先被买到、或由光伏/放电提供。

必须写下来的陷阱。很容易把能量平衡写成"充电只吃富余" c ≤ ĝ + d + (P − L)。这是错的，而且是静默错：

  1. 写成裸 c ≤ ĝ + d + (P−L)：因 c ≥ 0， 该式迫使 ĝ + d ≥ L − P，等于在每个情景里取消了紧急购电通道；且任何固定 ĝ 的执行 LP 立刻不可行。
  2. 改成 c ≤ ĝ + d + max(0, P−L)：在缺电时段退化为 c ≤ ĝ + d，而 e 同时还要补 L−P−ĝ−d —— 同一份 ĝ + d 既顶负载缺口又给电池充电，净凭空造电。实测全年总费掉到 2,773,754 元， 远低于完美预见下界 12,229,461 元。

这类错误的共同特征是结果看起来更好，只有拿"完美预见下界"当哨兵才抓得住 —— 这也正是 §2 那个 bug 能活到交付文件的原因。

终端条件

不要用"末端 SOC 的影子价格 λ"当值函数割平面近似 V(S) ≈ λ·S： 只要 λ > 0，日末 SOC 恒被灌到上限 10800，一维打靶没有内点解，是退化的。 改用日能量中性 ST,ω = S —— 全年能量中性的按日版本，无需标定、无歧义。在每日电价相同的问题 2 里跨日套利没有价格信号，逐日中性近似最优。

执行层与实测

EXEC=oracle 给储能日内完美预见 —— 不可实现，只当该政策的下界用。 EXEC=mpc 是因果滚动 MPC：每 6 槽重解一次长度 36 槽的 LP，只执行当前槽； 时域末端 SOC 跟踪日前计划轨迹，不能钉回"当前 SOC"（否则放电被执行、配套充电被实际富余削掉， 电池单向漏空：实测年末 SOC 掉到 1212 kWh、总费 32.8 M 元）。

§4替代算法二 · γ 可交付储能计划

如果需要一个开环、可复算、无模拟歧义的交付，把 SOC 递推里的 E[c̄] 换成"对覆盖率 γ 分位保证的可得充电"： 

c_t^min ≤ ĝ_t + d̂_t + q_{γ,t},    q_{γ,t} = { P_{ω,t} − L_{ω,t} } 的 (1−γ) 分位

γ=1 ⟹ q = minω(P−L)（全情景可交付）。 目标函数仍是 E[e] 的精确值（e 只依赖 (ĝ, d̂)，与 SOC 无关）， 所以给定 (ĝ, d̂) 的总费是闭式的 —— 消除了口径歧义。

重要保留。γ=1 的保证是对建模情景集（同星期几的 4 个历史日），不是分布无关的。 对全年 334 个实测日重放：按计划 cmin 执行得 16,017,281 元（放电被限 139,991 kWh）； 充电按 SOC 受限下的最优管理得 15,389,997 元（放电被限 30,677 kWh）。 两种口径下真实 SOC 最小值都恰为 1200（下限）。

如实报告时应取 15.39–16.02 M 元这个区间，而非 15,187,755。

§6自查记录

本文模型自身修掉的 6 个 bug 全部属于"结果看起来更好"的静默错，列出以便复核者信任其余数字。 其中第 4 条与队伍的病根属同一类。

  1. SOC 递推首行右端误置为 S —— S₀ 已由边界钉死，该式把 S₁ 顶到 2S = 12000 > 10800，不可行。
  2. 边界列表顺序写成 g|c|d|e|SOC，变量布局却是 g|c|d|SOC|e —— SOC 拿到 (0, None) 而 e 拿到 SOC 边界， 配上 −λ·SOCT 目标即为无界。HiGHS 报 "unbounded"，被断言误标成 "infeasible"。
  3. 不等式行块布局是 [r1 全部, r2 全部]，b_ub 却按 [s0,s0,s1,s1,…] 交替拼 —— 情景 0 恰好正确，掩盖了错误。
  4. "充电只吃富余"的两种写法，见 §3 的陷阱说明。
  5. λ 割平面终端条件退化（§3 终端条件）。
  6. MPC 时域末端钉回当前 SOC 导致电池单向漏空（§3 执行层）。

另：环境变量 TERM 与 shell 的终端类型变量重名，一度让终端条件开关静默失效；已改名 P2_TERM。

§7对论文的修改建议

  1. 不要报 13,832,465 元。它低于任何执行策略可达的下界。
  2. 若要保留"随机规划优于点预测"的叙事，前提是重做模型：按 §3 把储能降为追索变量， 并给出因果执行策略的成本，而不是照抄 d̂。
  3. 若要一个稳的交付数字，用 §4 的 γ=1 计划，报 15.19 M（情景内）/ 15.39–16.02 M（全年实测）。
  4. 无论走哪条路，必须同时报"完美预见下界"（12,229,461 元）作为哨兵 —— 本文实现过程中三次造出低于该下界的结果，全部是 bug。
