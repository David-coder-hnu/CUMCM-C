## 1. 计费口径：口径 A，以及它的两个推论

### 1.1 逐句推导（题面原文）

- 问题 2 第 40 行：「若每天的电价相同，而小区负载和光伏发电功率随时间变化，且微网提供的电能不可低于小区负载，
  如果低于负载，需向外网紧急购电，其电价是交易时刻电价的 5 倍。**除紧急购电费用外，其他时间段的购电费用均按计划购电量计算。**」
- 问题 3 第 54 行：「……**计划购电量高于调整购电量的部分，违约电价是交易时刻电价的 50%。调整购电量高于计划购电量的部分，
  超出部分的电价是交易时刻电价的 1.5 倍。总的购电费用包括计划购电费用、紧急购电费用和调整购电量的相关费用。**」

故**总费 = 计划购电费用 + 紧急购电费用 + 调整购电量的相关费用**，其中计划购电费用按问题 2 的定义
「按计划购电量计算」= `Σ p_t·ĝ_t·Δt`（**全额，take-or-pay**）。即**口径 A**：

```
总费 = Σ p·ĝ·Δt  +  0.5·Σ p·(ĝ − g)⁺·Δt  +  1.5·Σ p·(g − ĝ)⁺·Δt  +  5·Σ p·e·Δt
```

### 1.2 对照口径 B，以及为什么不能混比

口径 B 把第一项写成「按两者较小者付费」`p·min(g, ĝ)`。两者之差恰好是

```
口径A − 口径B = Σ p·(ĝ − g)⁺·Δt
```

也就是「多报却没用掉的那部分计划量」。**同一份轨迹在两种口径下差一个非零数**，所以两个口径下的总费
**不可直接比较**。v2（口径 B）报 14,722,577 元；把 v2 的同一条轨迹放到口径 A 下结算是 **14,908,236 元**（§7.3）。

> ⚠ **历史记录冲突，须以用户指令为准**：更早一个会话曾判定「计划购电费用读成 `p·ĝ`」有误并撤回该读法；
> 用户随后明确指定**「口径用 A」**。本文按用户指定执行。若再审此点，应先与用户确认，不要自行翻案。

### 1.3 推论 (1)：最优解上违约费恒为零

口径 A 下 `p·ĝ` 已全额付清，多报 1 kWh 的成本恰好是 `p`；少报 1 kWh 虽省下 `p·ĝ`，却要付 `0.5p` 违约金，
**净省 0.5p**——但少报的那 1 kWh 的真实用电仍要按 `1.5p`（可调段）或 `5p`（不可调段）补回来，
所以**净亏**。结论：**最优解必满足 `g ≥ ĝ`，违约项恒为 0**。

实测：定稿违约费 **0.00 元**，脚本内置断言。该推论只用于**验伪**（报出非零违约费即有 bug），
**不用于**反推最优分位——因为分位本身受下面 (2) 与 §2.1 的追索结构修正。

### 1.4 推论 (2)：0:00 的临界分位是**分块**的，且**理论值不等于实测最优**

`BLOCKS = [(0,36), (36,72), (72,108), (108,144)]` 是 0:00 / 6:00 / 12:00 / 18:00 四个发布时刻切出的四块。

- **第 0 块（0:00–6:00）不可调整**：6:00 档发布时它已经执行完了。静态推导：这块的缺电只能吃 **5p 紧急购电**，
  故报童临界比 = `c_u/(c_u+c_o) = 4p/(4p+p) = 0.80`。
- **第 1–3 块可调整**：缺电可用 1.5p 上调兜底，静态临界比 `0.5p/(0.5p+p) = 1/3`。

**两个理论值在实测下都不成立**，且**偏差方向相反**（实测 τ=(0.55, 0.42)）：

| 块 | 静态理论 | 实测最优 | 偏差 |
|---|---:|---:|---|
| 第 0 块（不可调整） | 0.80 | **0.55** | 显著**低于**理论 |
| 第 1–3 块（可调整） | 1/3 ≈ 0.333 | **0.42** | 略**高于**理论 |

第 0 块偏低的原因：那条推导假定 `ĝ` 是第 0 块的**唯一对冲手段**；而在追索计划里
**电池的充放电 `c,d` 本身逐情景对冲**，第 0 块的缺口能被情景内的放电吃掉一部分，
两侧代价被削平，有效临界分位因此下移。
第 1–3 块偏高的原因：1.5p 的「上调」是在**不完美预报**下做的，理论临界比只对「确定买得到」成立。

**所以 τ 只能扫、不能推。** 用**全天单一 τ** 会把这个结构差别抹平：
τ 取低则第 0 块欠买（只能按 5p 补救），τ 取高则后三块过买 —— 这正是单一 τ 下总费压成平台的原因。

> ⚠ 本节的静态推导只用于**解释方向**，不得用来论证「τ 的最优值」。§5.2 给出实测面板。

## 2. 模型结构：四层因果

| 层 | 时刻 | 决策 | 用到的信息 |
|---|---|---|---|
| 计划层 | 每天 0:00 | `ĝ`（144 槽，**一阶段承诺**）+ **逐情景** `c_ω, d_ω, e_ω, S_ω` | 附件 3 第 0 档预报 + 历史负荷（低需求日分组基线，§2.3）+ **同组历史日情景集** |
| 调整层 | 6:00 / 12:00 / 18:00 | 把后续时窗的目标净需求**上调** | 该时刻新发布的预报 + **当天已发生时段的实测** |
| 执行层 | 逐槽（10 min） | 跟随计划充放电；强制补放 | 实测负荷/光伏、当前 SOC |
| 结算层 | 事后 | 按口径 A 结算 | 实测轨迹 |

**只允许上调，不允许下调**：由 §1.3，下调一分钱也省不下来（`p·ĝ` 已付清），反而要付 0.5p 违约金，
所以下调在任何分位数下都不是最优。这条不对称正是口径 A 与 B 的分水岭。

### 2.1 计划层：**追索变量**（本轮主改动）+ 可靠性垫层

**这是本版相对 v3 的唯一结构性改动。** v3 的 `plan_day` 解一个**确定性**日前套利 LP，充放电 `c,d` 是
「预报下来该怎么做」的一个数；本版把它换成问题 2 的**两阶段**写法：

| | v3（确定性） | 本版（追索） |
|---|---|---|
| `ĝ` | 一阶段 | 一阶段（**唯一**的承诺变量） |
| `c, d, e, S` | 确定性单值 | **逐情景 ω 的追索变量** |
| 情景集 | — | 历史同组日（与问题 2 同思路） |
| 目标 | `Σp·ĝ` | `Σp·ĝ + (1/K)Σ_ω [超额 + 5p·e_ω]` |

**只有 `ĝ` 是拍板的承诺量，充放电随情景走。** 这解决了 v3 的一个结构性缺陷：
确定性 LP 只能按**一条**预报轨迹安排电池，预报偏了就整体偏；追索写法里电池**自己按情景对冲**，
承诺量 `ĝ` 则按情景分布取分位 ⇒ 两者分工，而不是让一个数同时干两件事。

- **可靠性垫层** `h`：把预报的**毛净需求** `L−P` 的误差分布的分位数垫在目标上，
  `Nt_t = F̂_t + h_t`。注意必须对准**毛净需求**——曾用「电池放完后的残余缺口」标定，
  那等于把放电算了两遍（残余里已扣过一次 `d`），计划据此少买，紧急购电暴涨。
- **分块分位** `TAU_B`：第 0 块与后三块用**不同** τ（§1.4）。

### 2.2 调整层：**水平校正**

预报误差里「整天整体偏高/偏低」那一支是**强自相关**的。只取残差分位抓不到它；
必须用当天**已发生时段的【实测负荷 / 基准负荷】比值** `r` 直接测出来，再按 `r` 缩放剩余时段的负荷预报：

```
r  = Σ_{t<a} load[d,t] / Σ_{t<a} L_base[d,t]          # 当天已发生部分
Ncor = r · L_base[d, a:b] − P̂[d, e, a:b]              # 校正后的目标
Rcor = actual_net[hist, a:b] − (r_p · L_base[hist, a:b] − P̂[hist, e, a:b])   # 同法校正的历史残差
Nt_adj[a:b] = max(Nt_adj[a:b], Ncor + Q_{τ'}(Rcor))
```

**消融：这一项在追索版下值 80,425 元**（§5.3）。注意它比 v3 时代的 132,972 元更小 ——
追索计划层已经把「整天偏高/偏低」那一支吸收了一部分，水平校正的边际价值随之下降（§5.4）。

### 2.3 基线口径：**低需求日分组**

`L_base` 是净需求基线（`F̂ = L_base − P̂` 里的负荷那一半），它同时进入三处：
计划层的 `Nt = F̂^(0档) + h`、**追索情景集的构造**、调整层的水平校正 `r` 的分母与残差基准。
所以它的构造口径直接决定整套预报修正的质量。

按暖机期（前 31 天，在计费窗口之前）的日均净负荷，把七天分成【低需求日】与【其余】两组，
`L_base[d]` = **过去 7 天内与第 d 天同组的日子**的负荷均值：

| 第 d 天是 | 过去 7 天（`range(d−7, d)`）里的同组日 | `L_base[d]` |
|---|---|---|
| **周五** | 上周五、上周六 | 这 2 天的均值 |
| **周六** | 上周六、上周五 | 同上（同 2 天） |
| 其余五天 | 上周一~上周四 + 周日（共 5 天） | 这 5 天的均值 |

本数据推导出的低需求日 = **{周五, 周六}**，依据（暖机期日均净负荷 kWh/日）：

| 星期 | 三 | 四 | **五** | **六** | 日 | 一 | 二 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 净负荷 | 530,299 | 535,631 | **254,734** | **256,970** | 537,426 | 526,753 | 528,455 |

**周五与周六需求水平几乎相同（相差 0.9%），故可互相借用**；其余五天彼此也接近（相差 ≤2.1%）。
分组规则**只喂暖机期**，在计费窗口开始前就固定下来 ⟹ **无前视**。

**为什么回看 7 天**：这是让低需求日拿到 2 个同组样本的**最小整数窗口**（span=6 只剩 1 个同组日，
span=5 一个都没有，只能退回全部历史）。负荷有季节性，窗口越近越准。

**时间口径与因果性**：`L_base[d]` 只用到严格早于第 d 天的历史日；`Nt_adj` 里的 `r` 只用当天**已发生**时段；
追索情景集只取第 d 天之前的同组日。与问题 2 同一套分组规则、同一套暖机期推导。

**消融：分组在追索版下值 610,446 元**（§5.3）。span 的完整扫描见 §5.4。

## 7. 关键结论与保留

### 7.1 ⚠ `G` 无上界：这是**读法选择**，不是自加假设了

**题面（附录 1）只给了储能「最大充放电功率 5000 kW」，并没有给微网与外网的联络线容量。**
v3 缺省取 `ĝ ≤ 5000 kW`（旋钮 `P3_GMAX`），那是**自加假设**；
**本版定稿改按题面字面读法放开上界**（`P3_GMAX=20000`，实际不触发）。

**放开不是免费的论证，是实测选出来的**。四象限（每格各自调平 τ，§7.2）显示：

- 在**确定性计划**下放开上界**更贵**（14,285,731 → 14,405,793）：日前 LP 会把电池
  **过度投入价格套利**，紧急购电从 76,784 kWh 涨到 **88,447～162,758 kWh**
  （随 τ' 取值；旧 τ'=0.55 处为 **243,780 kWh**），套利挤掉了可靠性。
- 在**追索计划**下放开上界**更便宜**（13,919,466 → 13,630,568）：追索写法把「承诺量」与
  「情景内怎么用电池」分开，套利不再挤占可靠性。

⇒ **「要不要给购电设上界」不能脱离计划层单独回答。** 本版选字面读法，
  并在 §7.2 同时给出保守读法下的可交付值，供读法变化时引用。

### 7.2 ★★ 对问题 2 的对照（必须按 `G_MAX` 读法分层 + 各自调平 τ 陈述）

**四种组合，每格都在自己的最优 τ 下测量**（span7；确定性= `P3_REC=0`）：

| 计划层 ＼ `G_MAX` 读法 | `G ≤ 5000`（保守） | `G` 无上界（字面，**本版交付**） |
|---|---:|---:|
| 确定性计划（= `代码/problem3_v3.py`） | 14,285,731（τ'=0.55） | 14,405,793（τ'=0.75，τ₀=0.90） |
| **追索计划（定稿）** | 13,919,466（τ'=0.30） | **13,630,568（τ'=0.42）** |

读法：

1. **追索计划在两种读法下都优于确定性计划**（−366,265 / −775,225），**这才是本轮的主要增益**。
2. **「放开上界」只在追索计划下有利**；确定性计划下设上界反而更好。
   ⇒ 旧归档那句「追索 + 无上界**必须一起开**才有效」**是在 τ 未调平时得出的，已在调平后失效**，勿再引用。
3. **保守读法下问题 3 现在也可交付了**（13,919,466），比 v3 定稿的 14,285,731
   **低 366,265 元（−2.56%）**；而问题 2 在该读法下**不可交付**（计划有 7,313 槽超 5000 kW）。
   ⇒ **换计划层的收益与读法无关。**
4. **本版交付（字面读法）合计比 v3 定稿低 655,163 元（−4.59%）** ——
   这是「换计划层」与「放开上界」两笔收益的叠加，**不是单开「放开上界」的效果**。

**哨兵（完美预见下界）**：

| 下界 | 数值 | 说明 |
|---|---:|---|
| 无上界读法 | **12,229,461 元** | 购电 20,187,649 kWh ｜ 零紧急 |
| `G ≤ 5000` 共同口径 | **12,406,053 元** | 购电 20,130,645 kWh ｜ 零紧急 |

两条哨兵由**各自口径**下的全年 LP 独立解出，两个数互不适用。
`problem2.py:237` 把购电变量建成 `(0, None)`，其哨兵 LP 解出 **g_max = 10,325.33 kW**（物理上限的两倍），

8. **`L_base` 的分组规则由暖机期推出、只喂暖机期**（§2.3），故无前视；
   但**它是在同一个数据集上推出来的**，若要主张分布无关的鲁棒性，需做样本外检验 —— 本问未做，
   **只主张「在这个数据集上显著更优」**。
9. **`L_base` 分组有用、残差分位分组有害**（§5.5），两处口径**有意不一致**；
   论文若只写「采用了低需求日分组」而不同时说明这一点，会被读成前后矛盾，**必须写清**。
10. **计划层与调整通道是部分替代品**（§5.3），**增益不可相加**；
    引用 1,289,323 / 132,972 元时必须注明它们属于确定性计划层。
11. **`P3_GRP` 已是脚本缺省** —— 复现任何"旧口径"基线都必须显式 `P3_GRP=''`，
    否则对照会静默退化成 `+0`；这个坑在诊断脚本里踩过一次。
12. **不要直接跑 `代码/problem3_recourse.py` 认定交付值** —— 它缺省 `P3_GMAX=5000`（旧读法）。
    交付入口是 `代码/run_problem3.py`；脚本启动时会打印配置自检行。
