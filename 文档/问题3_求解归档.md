## 1. 计费口径：口径 A，以及它的两个推论

### 1.1 逐句推导（题面原文）

- 问题 2 第 40 行：「若每天的电价相同，而小区负载和光伏发电功率随时间变化，且微网提供的电能不可低于小区负载，
  如果低于负载，需向外网紧急购电，其电价是交易时刻电价的 5 倍。**除紧急购电费用外，其他时间段的购电费用均按计划购电量计算。**」
- 问题 3 第 54 行：「……**计划购电量高于调整购电量的部分，违约电价是交易时刻电价的 50%。调整购电量高于计划购电量的部分，
  超出部分的电价是交易时刻电价的 1.5 倍。总的购电费用包括计划购电费用、紧急购电费用和调整购电量的相关费用。**」

故**总费 = 计划购电费用 + 紧急购电费用 + 调整购电量的相关费用**，其中计划购电费用按问题 2 的定义
「按计划购电量计算」= `Σ p_t·ĝ_t·Δt`（**全额，take-or-pay**）。即**口径 A**：

```
总费 = Σ p·ĝ·Δt  +  0.5·Σ p·(ĝ − g)⁺·Δt  +  1.5·Σ p·(g − ĝ)⁺·Δt  +  5·Σ p·e·Δt
```

### 1.2 对照口径 B，以及为什么不能混比

口径 B 把第一项写成「按两者较小者付费」`p·min(g, ĝ)`。两者之差恰好是

```
口径A − 口径B = Σ p·(ĝ − g)⁺·Δt
```

也就是「多报却没用掉的那部分计划量」。**同一份轨迹在两种口径下差一个非零数**，所以两个口径下的总费
**不可直接比较**。v2（口径 B）报 14,722,577 元；把 v2 的同一条轨迹放到口径 A 下结算是 **14,908,236 元**。
口径 A 下 v3 比它低 **195,411 元**。

> ⚠ **历史记录冲突，须以用户指令为准**：更早一个会话曾判定「计划购电费用读成 `p·ĝ`」有误并撤回该读法；
> 用户随后明确指定**「口径用 A」**。本文按用户指定执行。若再审此点，应先与用户确认，不要自行翻案。

### 1.3 推论 (1)：最优解上违约费恒为零

口径 A 下 `p·ĝ` 已全额付清，多报 1 kWh 的成本恰好是 `p`；少报 1 kWh 虽省下 `p·ĝ`，却要付 `0.5p` 违约金，
**净省 0.5p**——但少报的那 1 kWh 的真实用电仍要按 `1.5p`（可调段）或 `5p`（不可调段）补回来，
所以**净亏**。结论：**最优解必满足 `g ≥ ĝ`，违约项恒为 0**。

实测：定稿违约费 **0.00 元**，脚本内置断言。该推论只用于**验伪**（报出非零违约费即有 bug），
**不用于**反推最优分位——因为分位本身受下面 (2) 的修正。

### 1.4 推论 (2)：0:00 的临界分位是**分块**的，不是单一值

`BLOCKS = [(0,36), (36,72), (72,108), (108,144)]` 是 0:00 / 6:00 / 12:00 / 18:00 四个发布时刻切出的四块。

- **第 0 块（0:00–6:00）不可调整**：6:00 档发布时它已经执行完了。这块的缺电只能吃 **5p 紧急购电**，
  故报童临界比 = `c_u/(c_u+c_o) = 4p/(4p+p) = 0.80`。
- **第 1–3 块可调整**：缺电可用 1.5p 上调兜底，理论临界比 `0.5p/(0.5p+p) = 1/3`。

但**纯理论值 1/3 被实测证伪**——实际最优 ≈ 0.55。原因：1.5p 的「上调」本身是在**不完美预报**下做的，
理论临界比只对「确定买得到」成立。**所以 τ 只能扫、不能推。**

用**全天单一 τ** 会把这个结构差别抹平：τ 取低则第 0 块欠买（只能按 5p 补救），τ 取高则后三块过买。
这正是单一 τ 下总费在 0.65–0.70 压成平台的原因。

## 2. 模型结构：四层因果

| 层 | 时刻 | 决策 | 用到的信息 |
|---|---|---|---|
| 计划层 | 每天 0:00 | `ĝ`（144 槽）+ 计划充放电 `c, d` | 附件 3 第 0 档预报 + 历史同星期几负荷 |
| 调整层 | 6:00 / 12:00 / 18:00 | 把后续时窗的目标净需求**上调** | 该时刻新发布的预报 + **当天已发生时段的实测** |
| 执行层 | 逐槽（10 min） | 跟随计划充放电；强制补放 | 实测负荷/光伏、当前 SOC |
| 结算层 | 事后 | 按口径 A 结算 | 实测轨迹 |

**只允许上调，不允许下调**：由 §1.3，下调一分钱也省不下来（`p·ĝ` 已付清），反而要付 0.5p 违约金，
所以下调在任何分位数下都不是最优。这条不对称正是口径 A 与 B 的分水岭。

### 2.1 计划层：可靠性垫层 + 日前套利 LP

- **可靠性垫层** `h`：把预报的**毛净需求** `L−P` 的误差分布的分位数垫在目标上，
  `Nt_t = F̂_t + h_t`。注意必须对准**毛净需求**——曾用「电池放完后的残余缺口」标定，
  那等于把放电算了两遍（残余里已扣过一次 `d`），计划据此少买，紧急购电暴涨。
- **日前套利 LP** `plan_day`：直接按分时电价在 144 槽上联合解出 `ĝ, c, d`，
  低价充、高价放。**这是最大的一根杠杆**——题面第 7 行明确认可「在电价较低或分布式能源有剩余电量的
  时间段为储能设备充电，并在电价较高的时间段释放电能」。实测储能日吞吐约 14,965 kWh，
  往返效率 `d/η ÷ c = η² = 0.81`。

### 2.2 调整层：**水平校正**（v3 相对 v2 增益的主来源）

预报误差里「整天整体偏高/偏低」那一支是**强自相关**的。只取残差分位抓不到它；
必须用当天**已发生时段的【实测负荷 / 基准负荷】比值** `r` 直接测出来，再按 `r` 缩放剩余时段的负荷预报：

```
r  = Σ_{t<a} load[d,t] / Σ_{t<a} L_base[d,t]          # 当天已发生部分
Ncor = r · L_base[d, a:b] − P̂[d, e, a:b]              # 校正后的目标
Rcor = actual_net[hist, a:b] − (r_p · L_base[hist, a:b] − P̂[hist, e, a:b])   # 同法校正的历史残差
Nt_adj[a:b] = max(Nt_adj[a:b], Ncor + Q_{τ'}(Rcor))
```

`problem3.py` 的 `solve_stage` 里有这个比值修正，v3 最初漏掉了，是最大的缺口。
补上后紧急购电 148,649 → 59,241 kWh。**消融：这一项值 391,377 元。**

## 7. 关键结论与保留

### 7.1 ⚠ 一条自加假设：`ĝ ≤ 5000 kW`

**题面（附录 1）只给了储能「最大充放电功率 5000 kW」，并没有给微网与外网的联络线容量。**
v3 缺省把购电功率上界取成 `P_MAX = 5000 kW`，这是**自加假设**（旋钮 `P3_GMAX`）。

实测（见 `代码/诊断/diag_sentinel_p2p3.py` 与记忆 `cumcm-c-购电功率上限与哨兵`）：

- 放开这个上界（`P3_GMAX=inf`）**反而更贵**：15,070,506 元 vs 缺省 14,712,825 元（**+35.8 万**）。
  原因：无上界时日前 LP 把电池**过度投入价格套利**，紧急购电从 9.6 万涨到 **26.3 万 kWh**——
  套利挤掉了可靠性。**所以保留上界既保守又更优。**
- 该假设使 v3 的解在**两种读法下都可行**（`结果/result3.xlsx` 有 **0** 个槽超过 5000 kW）。

### 7.2 对问题 2 的对照（**两条哨兵不可并列**）

`problem2.py:237` 把购电变量建成 `(0, None)`，其哨兵 LP 解出 **g_max = 10,325.33 kW**（物理上限的两倍），
所以它报出的下界 **12,229,461 元偏低**。加回 `G ≤ 5000` 后同一条 LP 给出 **12,406,052.74 元**，
与 `problem3_v3.sentinel()` **精确到分相同**——两个独立写的 LP 给出同一个数，是很强的交叉验证。

`结果/result2.xlsx` 的交付计划**有 7,801 / 48,096 个槽超过 5000 kW，峰值 10,325.3 kW**，
即问题 2 的方案**只在「购电无功率上限」的字面读法下可行**。

| | 问题 2 | 问题 3 |
|---|---:|---:|
| **实际执行总费（交付值，对等口径）** | **15,134,192 元** | **14,712,825 元** |
| 　规划层同账本值（参考） | 15,187,755 元 | 14,712,825 元 |
| 账本结构 | `p·ĝ + 5p·e` | `p·ĝ + 1.5p·(g−ĝ)⁺ + 5p·e`（违约项 = 0） |
| 购电功率峰值 | 10,325 kW（7,801 槽越限，**334 天无一幸免**） | **5,000 kW**（0 槽越限） |
| 自身口径哨兵 | 12,229,461（无上界） | 12,406,053（含上界） |
| 高出自身哨兵 | 23.8% | **18.6%** |
| **共同口径**（都加 5,000 kW 上界）哨兵 | **12,406,053** | **12,406,053** |

> **⚠ 「交付值」取法要对等。** 问题 2 的 `result2.xlsx` 记录的是**实际因果执行轨迹**
> （15,134,192 元），其规划层同账本值才是 15,187,755 元；问题 3 的 14,712,825 本身即实际执行值。
> 故**对等口径 = 15,134,192 vs 14,712,825**。

**结论：问题 3 比问题 2 便宜 421,367 元（2.8%）**（两问各按规划层比则为 474,930 元 / 3.1%），
**且在两种读法下都可行；问题 2 的只在一种读法下可行。**
故「问题 3 优于问题 2」的结论**不依赖读法选择**。

> **⚠ 论文必须同时交代两点**：
> ① 两问总费是**各自题面口径**下的数（问题 2 无调整通道）。问题 3 多出的调整通道本就该让它更便宜，
>    所以这是**同族账本**的比较，**不是同一账本**——不要写成"同一模型下的改进"。
> ② 问题 2 的哨兵 12,229,461 与问题 3的 12,406,053 **不可并列**；对照时必须统一取 **12,406,053**。

### 7.4 必须写明的保留

1. **分位是扫描出来的平台中心，不是尖点最优**（§5.2，0.50–0.60 极差 4.0 万元）。
   论文不得声称「求得最优 τ」。
2. **`ĝ ≤ 5000 kW` 与「年末 SOC = 6000」都是自加假设**，题面未要求，须声明并做敏感性（§7.1）。
3. **18:00 档几乎不增值**（26,743 元 / 0.18%），如实交代，不辩护。
4. **完美预见下界 12,406,053 元必须每次报数时同时给出**，且**必须说明它含 `ĝ ≤ 5000 kW`**；
   任何低于它的结果都是 bug。
5. 同星期几情景集要往前翻约 5 个月，**跨季节**，是该场景构造法的固有代价。
